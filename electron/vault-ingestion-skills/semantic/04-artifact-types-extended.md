# Artifact types (extended)

Choose one primary `type` per artifact.

## Core types

| Type | Use when |
|------|----------|
| `concept` | Explains what/why/how of one idea |
| `rule` | Normative requirements (`must`, `must not`) |
| `overview` | Folder navigation index + retrieval routing |
| `decision` | Recorded choice with alternatives and consequences |

## Extended types

| Type | Use when |
|------|----------|
| `pattern` | Reusable architectural or design pattern |
| `anti_pattern` | Recurring mistake to avoid |
| `workflow` | Multi-step process or operational flow |
| `entity` | Domain object or bounded context definition |
| `glossary` | Terminology definition |
| `incident` | Postmortem or failure analysis |
| `constraint` | Hard technical or business limit |
| `heuristic` | Empirical guideline (non-normative) |
| `mapping` | Cross-layer execution note linking business intent, technical implementation, and operational behavior (project vaults) |

One primary type per file. Map each type to the appropriate planning template when building `vaultIngestionPlan`.
